# NEXT for DeepSeek Harness

NEXT 为 DeepSeek Harness 提供按会话启用的执行与上下文优化。项目以 [MIT 许可证](LICENSE) 开源，是社区插件，**非 DeepSeek 官方产品**。

仓库：[xhnhhnh/dsh-next](https://github.com/xhnhhnh/dsh-next)

当前源码版本为 **0.8.0 preview**，目标宿主为 **Windows 上的 DeepSeek Harness 0.2.1-alpha.5**。它依赖该 alpha 版本的原生插件接口，其他宿主版本与平台尚未验证。最新历史原生测试在 `production-native-service-present`（生产服务可用性）检查处失败，0.8.0 的完整宿主验收、安装验收及真实前端对照尚未完成。不能把源码功能或单测通过解释为生产可用、实际节省或效果提升。详见 [验证记录](docs/VALIDATION.md)。

## 会话开关

聊天输入框右侧的 **NEXT** 按钮仅切换当前会话状态，保留草稿，不发送消息、不调用模型。新聊天默认关闭，状态随会话保存；子代理继承父会话设置，本地显式状态优先。运行中的调用按原状态结束，后续调用使用新状态。

- `/next on`：开启当前会话。
- `/next off`：关闭当前会话。
- `/next status`：查看状态、可用能力及启用期间统计，不调用模型。

NEXT 保留用户选择的模型、思考强度、Max、Plan 和 Goal。不增加模型分类请求、独立规划、审查或自动续行循环，也不依赖 Adaptive Mode。

## 设置与模型标签

打开 **设置 → NEXT** 查看模型目录、默认偏好、标签、项目检查和价格等设置。

DeepSeek 官方账号与官方 API 中相同模型 ID 使用一个设置入口，修改后共享模型优化策略。实际调用仍走用户选择的路由，**价格、用量和费用分别按真实路由处理**；其他提供方与不同模型 ID 不合并。

模型可以关联标签并设置独立覆盖。优先级为：**默认偏好 → 标签依列表顺序叠加 → 模型独立覆盖**。模型身份标签用于组织相应模型的策略，不锁定服务方滚动别名背后的权重版本。标签名称本身不注入系统提示；标签可选，不自动关联模型。

可调偏好包括输出语言、回复详略、重复读取优化、执行效率提示、按需方法指导、精准验证建议、按收益并行建议、Token 明细展示、主动自动化、修改后验证、只读子代理及其预算。指导选项只提供工作建议；真正的验证必须有实际检查结果。执行效率提示默认关闭，三个指导子项只有总开关打开后才生效。

设置使用宿主配置文档保存，不发送消息、不切换模型。会话 NEXT 关闭时不应用优化策略或追加自动工作。模型与标签设置跨会话共享，会话开关单独保存。

## 0.8.0 preview 的能力

| 能力 | 行为与边界 |
| --- | --- |
| 可用状态 | `nextCapabilities` 会话投影供设置页和 `/next status` 展示优化、验证、检索、自动子代理的状态及原因。调用前隐藏不可执行的可选工具，执行时仍重新检查。 |
| 重复读取 | 原生文件读取仍正常执行。仅在路径、范围、内容和版本一致，且前次全文仍在模型可见上下文时，用短引用替代重复的模型侧全文。程序原始结果与日志保留。 |
| 项目命令检查 | 扫描脚本只生成候选；用户登记后，才可通过宿主原生工具与权限链执行准确命令。登记绑定工作目录、超时、脚本与依赖锁文件。 |
| 文件产物检查 | 支持 CSV、JSON、Markdown 的基础结构与登记条件检查，兼容原有 JSON 语法和 JSON Schema 检查。结构通过不等于完成内容或业务验收。 |
| 只读子代理 | 通过宿主调度，允许原生 `read`、`glob`、`grep` 定位信息；不提供编辑或 Shell 权限，不递归委派 NEXT 子代理。 |
| 用量与费用 | 复用原生 Token 入口，展示 NEXT 启用期间可归属请求的调用、Token、耗时与估算费用。缺失数据为“未知”。 |

网页、未知 MCP 与第三方插件的结果不套用文件去重。联网与其他办公格式继续使用宿主已有能力；NEXT 不宣称已完成这些格式的专门验收。

### 登记项目检查

在项目检查设置中选择工作目录，扫描 `package.json` 中的 `test`、`typecheck`、`check`、`lint`、`build` 脚本，再明确登记候选。扫描不执行脚本、不安装依赖。也可登记文件产物及所需列名或文本。

脚本、绑定文件或锁文件变更会使命令登记过期，需要检查并重新登记。连续文件修改会合并检查；命令结果不跨任务缓存，后续修改使原有证据过期。权限拒绝、取消、超时、无法完整观察输入或范围超限时，不返回虚假的通过。

`next_verify` 返回检查范围、实际结果和产物路径，区分通过、失败、未知、过期。结果形成审计记录，并给模型一次简短通知。历史通过只说明当时对应输入的检查结果。

原有 JSON 配置仍支持，例如：

```yaml
verificationChecks:
  - id: app-config
    workspace: C:/your-project
    kind: json-schema
    file: config.json
    schemaFile: config.schema.json
```

`workspace` 必须为绝对目录，文件位于该目录内。命令绑定应通过设置页扫描生成，不要填写猜测的摘要。自动验证仅执行已登记检查，并同时受 NEXT、主动自动化和修改后验证开关控制。

### 价格、预算与统计

设置页可维护精确 `provider/model` 的价格及有效期，单位为 **CNY / 百万 Token**。请按实际服务等级和时段核实价格；默认不内置永久有效的单价。官方账号与 API 的策略共享不代表价格共享。

自动只读子代理每次请求前预留最坏费用，结束且有完整用量后才结算估算费用。缺少价格、价格过期、预算不足或存在未知请求预留时，停止新的自动付费派发，主任务可继续。配置预算限制 NEXT 自动子代理，不是整个主会话的费用上限。

原生 Token 总计与 NEXT 启用期间统计的范围不同，不应相加。可归属的宿主请求包含辅助调用与子代理；第三方直接 HTTP/SDK 请求不在覆盖范围内。流式累计用量只结算一次；未知费用不会记作零。金额是配置单价估算，供应商账单才是实际收费依据。

## 安装与卸载

本仓库公开源码，尚不将 0.8.0 preview 声明为完成生产验收的稳定版。构建方法见 [开发说明](docs/DEVELOPMENT.md)。

安装前备份目标 profile 的 `package.json`、`cordis.yml`、`cordis.patch.yml`、`pnpm-lock.yaml`、`pnpm-workspace.yaml` 及已有 NEXT 包。使用与目标桌面应用配套的 CLI：

```powershell
dsh plugin --profile desktop add <插件包的绝对路径.tgz>
```

卸载前等待当前调用结束，使用同一套 CLI：

```powershell
dsh plugin --profile desktop remove @local/dsh-next
```

按宿主提示重新加载插件或在任务结束后重启应用。卸载后原生 Token 入口恢复；会话日志与用户文件应保留。不要删除共享 `.dsh` 目录。需要回退时安装备份旧包，仅撤销本次 NEXT 配置差异，避免整份旧配置覆盖之后新增的数据。

## 开发与验证

需要 Node.js 22 或更新版本：

```powershell
npm install
npm run build
npm test
npm run check
```

这些命令不发起模型调用。真实宿主验证需要本机兼容 Harness，付费评测必须另行明确授权，并满足价格、账本和预算检查。完整环境和评测约束见 [开发说明](docs/DEVELOPMENT.md)。

NEXT 借鉴按需方法、有效证据与精简上下文的原则；不承诺固定节省比例，也不把局部测试推广为所有任务的收益。
